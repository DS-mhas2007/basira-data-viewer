# MIZYAi

منصة عربية (RTL) لتحليل ملفات CSV وXLSX داخل المتصفح: فحص جودة البيانات، تنظيفها، رسوم بيانية، تقارير PDF، وسؤال البيانات بالعربية بمساعدة الذكاء الاصطناعي.

## ما الذي يعمل محلياً وما الذي يُرسل؟

- **محلياً بالكامل:** قراءة الملف، الفحص، التنظيف، الاستعلامات والرسوم. تُنفَّذ عبر DuckDB-WASM داخل المتصفح، والملف الأصلي لا يُرفع.
- **ميزات الذكاء الاصطناعي:** تُرسل إلى مزوّد النموذج سؤالك وأسماء الأعمدة وأنواعها وعيّنة صغيرة (حتى 8 صفوف في الواجهة الحالية؛ ويقبل الخادم 10 كحد أقصى)، وفي محادثة «اسأل MIZYAi» نتائج الاستعلامات التي ينفّذها الوكيل (معاينة تصل إلى 30 صفاً لكل نتيجة). تُحفظ المحادثة في حساب المستخدم ما لم يفعّل «لا تحفظ محادثتي». هذا المفتاح يوقف الحفظ في Supabase فقط، ولا يمنع إرسال السؤال ونتائج الأدوات اللازمة إلى مزوّد النموذج.

## التقنيات

- TanStack Start (React 19, Vite 8) وTailwind 4 وshadcn/ui
- DuckDB-WASM لتنفيذ SQL في المتصفح (يُحمَّل من jsDelivr بسبب حد 25MB لملفات Cloudflare)
- Supabase للمصادقة (يشمل الدخول كزائر) وقاعدة البيانات
- Vercel AI SDK مع MIZYAi AI Orchestrator (Cloudflare Workers AI ومزوّدين احتياطيين)
- PWA عبر vite-plugin-pwa (يعمل دون اتصال بعد الزيارة الأولى)
- Vitest للاختبارات، وCI عبر GitHub Actions وbun

## حدود التصدير

- CSV وExcel: أول 200,000 صف من العرض الحالي كحد وقائي للمتصفح، مع تنبيه عند اختصار التصدير.
- التقرير التفاعلي HTML: أول 200 صف في جدول كل استنتاج، وأول 12 نقطة في الرسم.
- PowerPoint: ملخص الاستنتاجات يعرض حتى 5 عناصر، وصفحات التفاصيل حتى 10 استنتاجات عند تفعيلها، وأول 12 نقطة في كل مخطط؛ تظهر ملاحظة وتنبيه عند الاختصار.

## التشغيل محلياً

```bash
bun install        # أو: npm install --legacy-peer-deps
cp .env.example .env   # واملأ القيم
bun run dev
```

أوامر مفيدة: `bunx tsc --noEmit` و`bunx vitest run` و`bunx vite build`. اختبار المتصفح الدخاني: راجع التعليق أعلى `e2e/smoke.mjs`. ملف القفل المعتمد هو `bun.lock`.

## مزوّدو الذكاء الاصطناعي (Hybrid AI)

تستخدم MIZYAi طبقة توجيه موحّدة على الخادم. المسار الأساسي هو Worker مستقل على Cloudflare باستخدام نموذج Gemma 4 الداعم لاستدعاء الأدوات، ويمكن إعداد مزوّدين خارجيين كبدائل:
- Cloudflare Worker الخاص بـ MIZYAi عبر `MIZYAI_WORKER_URL` و`MIZYAI_WORKER_API_KEY` (المسار المفضل)
- Gemini API عبر `GEMINI_API_KEY`
- Groq عبر `GROQ_API_KEY`
- OpenRouter عبر `OPENROUTER_API_KEY` (اضبط نموذجاً مجانياً متاحاً في حسابك)
- Cloudflare Workers AI عبر `CLOUDFLARE_API_TOKEN` و`CLOUDFLARE_ACCOUNT_ID`

الأولوية الافتراضية: Worker الخاص بـ MIZYAi ثم Gemini ثم Groq ثم OpenRouter ثم Cloudflare المباشر. طلبات التخطيط والتقارير تنتقل إلى مزوّد تالٍ عند أخطاء الشبكة أو تجاوز المعدل أو أخطاء الخادم المؤقتة. لا يحدث fallback عند أخطاء المصادقة أو الطلبات غير الصالحة. المحادثة المتدفقة تستخدم أول مزوّد مُعدّ؛ لا يمكن تبديل المزوّد بأمان بعد بدء البث.

**مهم:** الحصص المجانية ليست غير محدودة وقد تتغير أو تتوقف. يوفّر Workers AI حالياً 10,000 Neurons يومياً دون رسوم؛ في خطة Workers Free تتوقف الطلبات بعد استهلاك الحصة، أما الاستخدام الأعلى فيتطلب الترقية إلى خطة مدفوعة. لا توجد تكلفة اشتراك من MIZYAi في هذا المسار، ولا تفعّل خطة مدفوعة دون مراجعة التكلفة أولاً. أضف المفاتيح في أسرار الخادم لدى بيئة الاستضافة، وليس في ملفات الواجهة أو مستودع GitHub. لا تستخدم بادئة `VITE_` لمفاتيح AI.

تُرسل للمزوّد فقط المدخلات اللازمة للمهمة: سؤال المستخدم، مخطط الأعمدة وعينة صغيرة في مخطط SQL، أو ملخص نتائج التحليل في التقرير. لا يُرفع ملف CSV/XLSX الأصلي في مسار التحليل المحلي الموثّق. راجع سياسات الاحتفاظ لدى المزوّد قبل إرسال بيانات حساسة.

راجع [دليل إعداد المزوّدين](docs/mizya/AI_PROVIDER_SETUP.md) لمتغيرات البيئة وحدود الخصوصية.

## الإعداد على Supabase

1. طبّق ملفات `supabase/migrations/` بالترتيب.
2. فعّل **Anonymous sign-ins** (Authentication → Providers). مطلوب للتجربة كزائر.
3. متغيرات الخادم: إعداد `MIZYAI_WORKER_URL` و`MIZYAI_WORKER_API_KEY` لتفعيل Worker، مع مفاتيح مزوّدي fallback عند الحاجة، و`SUPABASE_SERVICE_ROLE_KEY`. القائمة الكاملة في `.env.example`.
4. اختبار نظام الحصص: `npm i --no-save @electric-sql/pglite && node supabase/tests/ai_quota.mjs`.

## الحصص

حدود الاستخدام في جدول `plan_limits`: زائر 5 عمليات AI مدى الحياة، وحساب مجاني 30 عملية AI شهرياً. خطط `pro` و`team` أرقامها مؤقتة ولا يوجد دفع بعد. يُحسب كل سؤال مرة واحدة حتى لو استدعى النموذج أدوات عدة (`action_id`).
